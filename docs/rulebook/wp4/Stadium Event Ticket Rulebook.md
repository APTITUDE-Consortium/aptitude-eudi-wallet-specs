## 1 Introduction

### 1.1 Document scope and purpose
This Rulebook defines the Stadium Event Ticket Attestation for use in the Aptitude consortium.
The Stadium Event Ticket attestation proves that a person holds a valid admission right for a specific sports match, entertainment event, or other gathering during the specified validity period. It enables a relying parties to verify access rights and ticket entitlement statuses, using the EUDI Wallet / FastID Wallet.
The attestation is issued by an authentic source, such as a sports club, venue operator, or ticketing platform. The holder is the one who possesses the ticket in their wallet. 
The attestation enables the holder to present proof of admission through an EUDI Wallet / FastID Wallet using selective disclosure or offline proximity presentation. It eliminates the need for paper tickets, static screenshots, or manual barcode scanning.
The attestation will also support additional entitlements and can be linked to credentials like student cards, municipal social cards or city passes. Which could allow the user to gain discounts or other benefits.Once verified, the issued Stadium Event Ticket carries the entitlement status directly, ensuring that no raw ID document, student card or civil identity attributes are exposed.

### 1.2 Document structure
This Rulebook is structured as follows:
Chapter 2, which describes the attestation attributes and metadata in an encoding-independent manner.  
Chapter 3, which specifies how the attestation attributes and metadata are encoded in case the attestation complies with [ISO/IEC 18013-5] and/or [SD-JWT VC] and/or [W3C VCDM v2.0].   
Chapter 4, which specifies attestation usage.  
Chapter 5, which defines how trust anchors for attestation verification can be obtained.  
Chapter 6, which defines attestation revocation mechanisms.  
Chapter 7, which provides compliance information.  

### 1.3 Key words
This document uses the capitalised key words 'SHALL', 'SHOULD' and 'MAY' as specified in [RFC 2119], i.e., to indicate requirements, recommendations and options specified in this document.
In addition, 'must' (non-capitalised) is used to indicate an external constraint, i.e., a requirement that is not mandated by this document, but, for instance, by an external document. The word 'can' indicates a capability, whereas other words, such as 'will', and 'is' or 'are' are intended as statements of fact.

## 3 Attestation encoding

### 3.1 ISO/IEC 18013-5-compliant encoding
For proximity presentation at stadium turnstiles, the attestation SHALL be issued in ISO/IEC 18013-5 mdoc format.
Document type: org.iso.23220.ticket.stadium.1
Encoding parameters:
- tstr, uint, bstr, bool and tdate are CDDL representation types defined in [RFC 8610].
- All attributes having encoding type tstr SHALL have a maximum length of 150 characters.
- Dates are represented as tdate formatted in ISO 8601 UTC.

| Data Identifier | Attribute identifier | Encoding format | Namespace |
|---|---|---|---|
| attestation_legal_category | attestation_legal_category | tstr | org.iso.23220.ticket.stadium.1 |
| ticketIdentifier | ticket_id | tstr | org.iso.23220.ticket.stadium.1 |
| eventId | event_id | tstr | org.iso.23220.ticket.stadium.1 |
| accessZone | access_zone | tstr | org.iso.23220.ticket.stadium.1 |
| validFrom | valid_from | tdate | org.iso.23220.ticket.stadium.1 |
| validUntil | valid_until | tdate | org.iso.23220.ticket.stadium.1 |
| seating | seating | map | org.iso.23220.ticket.stadium.1 |
| ticketCategory | ticket_category | tstr | org.iso.23220.ticket.stadium.1 |

## 4 Attestation usage
This attestation is intended for stadium entry and venue access within the EUDI Wallet ecosystem.
Key requirements:
- PID Request: Relying Parties SHALL NOT request Person Identification Data (PID) during gate entry. Civil identity is decoupled from ticket presentation to protect privacy and maintain throughput.
- Device Binding: The credential SHOULD be cryptographically bound to the Wallet Unit's device key (holderBindingKey) to prevent ticket cloning, screenshot sharing, or unauthorized resale.
- Presentation Protocol: Gate presentation SHALL use OpenID4VP 1.0 over Bluetooth Low Energy (BLE) or Dynamic QR Code for verification.

## 5 Trust anchors
To verify a Stadium Event Ticket Attestation, Relying Party turnstiles obtain the issuer's public key from the Trusted Issuer List  established under APTITUDE WP2 / WP4 governance.
Verification steps:
- Turnstile reader receives the presented mdoc or SD-JWT VC through BLE/QR.
- Verifier extracts the iss identifier and looks up the issuer certificate on the Trusted Issuer List.
- Verifier verifies the digital signature over the credential payload using the issuer's public key.
- Verifier confirms that the issuer is authorized to issue credentials of type stadium_event_ticket.

## 6 Revocation
Revocation and status management follow the OAuth 2.0 Attestation Status List / Bitstring Status List specification:
- The ticket issuer maintains a bitstring status list indicating whether a ticket index is valid, redeemed, or cancelled.
- Turnstiles periodically fetch or cache status list bitstrings to support offline local checks.
- Upon initial gate entry, the turnstile marks the ticket index as redeemed to prevent re-entry.

## 7 Compliance
This Rulebook complies with the European Digital Identity Framework (Regulation (EU) 2024/1183) for non-qualified Electronic Attestation of Attributes. It adheres to ARF Annex 2 Topic 12 (Attestation Rulebooks), Topic 7 (Revocation), and Topic 10 (Issuance). Data processing complies with GDPR Article 5(1)(c) data minimisation requirements.
